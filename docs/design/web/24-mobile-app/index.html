§1 调研：Lody 移动端github.com/LodyAI/Lody · 手机端闭源，仓库里只有 cli 与 electron

Lody 的 iOS 走 App Store 与 TestFlight，Android 发签名 APK；仓库里没有手机端代码，能模仿的是功能清单和分工，不是实现。它的文档（site-docs/(features)/mobile.mdx、notification.mdx）把手机端定义得很窄，恰恰是值得抄的地方：

通知（三种事件）

对话结束 · 请求权限 · 发生错误。设置 › 通用 › 推送通知 一个开关。桌面是浏览器通知，手机是原生推送。

iOS 实时活动

锁屏和灵动岛上显示正在跑的 agent 状态；agent 要权限时发一条可直接操作的实时活动，在锁屏上批。

监控进度

实时终端输出、文件改动、会话 diff 与 review 评论、图片预览（长按分享保存）。

浏览项目文件

Projects 标签打开项目 → Files 浏览目录树、预览文本。不用先建会话。手机不能编辑。

离线

缓存的对话、保存过的 diff 离线能看；联网后自动同步。

派活

从手机把任务派到任何一台已连接的机器；权限请求、进度、改动在各端同时可见。

它为什么做得顺

两个架构决定让手机端变成薄客户端：agent 走 ACP 协议给结构化消息（权限请求是一条带 id 的消息，不是屏幕上的一个框）；数据靠 Loro CRDT 经它的云端中转，手机端天然离线优先。Roami 的底座是 tmux 加转录文件、手机直连自己的机器，这两件事得自己做：「权限请求」要从抓屏里认出来（已经在做，见 §2），「离线」要自己缓存。

抄功能清单，不抄架构。Roami 保留 tmux 底座的理由（agent 原样、任何 TUI 都能跑、不依赖云）在 22 稿已经定了，手机版不推翻它。

§4 路线：PWA + Web Push，Android 用 TWA 包成 App不是 Electron（它出不了手机），不是 Capacitor（收不到 Web Push），也不重写

先定约束，再选技术：Roami 是自托管软件，任何人 install.sh 一下就是一个独立部署。手机版因此不能有「Roami 项目方运营的中心推送服务」，也不能要求部署者去申请 FCM / APNs 账号。能满足这条的推送只有一种：Web Push——标准协议，每个部署首次启动自己生成一对 VAPID 密钥，浏览器厂商的推送网关免费、匿名、不需要注册。

路线是什么推送中心依赖结论
PWA 加到主屏现有前端；iOS 16.4+ / Android Chrome 都支持安装、推送、角标Web Push ✓无iOS 与 Android 的底座
Android TWA（Bubblewrap）谷歌官方的「把 PWA 包成 Play 应用」：跑在 Chrome 引擎里，有图标、全屏、能上 Play；部署者一条命令打自己的 APKWeb Push ✓（就是 Chrome 的）无Android 的「App」
Capacitor原生 WebView 壳 + 原生插件WebView 收不到 Web Push；要推就得 FCM / APNs，那是发布者的账号 → 需要中心中转有与自托管冲突
Electron桌面壳——出不了手机
React Native / Flutter / 原生重写同 Capacitor 的账号问题有不值
iOS 没有开发者账号也没关系了：这条路线 iOS 本来就不出包。有账号的部署者想上 App Store 时，把 PWA 用 WKWebView 包一层即可，推送仍走 Web Push 以外的通道需另议——不在本稿范围。
「PWA 算真正的 App 吗？」从用户角度：主屏图标、全屏、锁屏通知、角标、后台收推送、Android 上还在 Play 商店里——都有。缺的只有 iOS 灵动岛实时活动，那需要苹果账号，本稿不做。Lody 的手机端好用不是因为原生，是因为它给手机单独设计了页面，§5 做的就是这件事。

批权限的链路

  1. 后端每轮 /projects 已经在抓屏算 sessionWaiting；把「上一轮 false、这一轮 true」这个翻转发成 session.waiting 事件，带 tail（摘要）和从抓屏解析出的选项（复用 detectPrompt 的 Go 移植 waiting.go，补一个「选项列表」返回）。3 秒去抖，避免 TUI 重绘残帧。
  2. 推送体：标题 = 会话名，正文 = tail，category=permission，actions = 允许 / 拒绝（只在选项能确定是 y/n 或「1. Yes」这类时才带 action，否则只带「打开」）。
  3. 点「允许」：Service Worker 的 notificationclick 在后台直接 POST /sessions/:name/keys {"keys":["Enter"]}（或对应数字），不打开页面；成功后把通知改成「已允许」，失败则打开会话页。白名单不变。
  4. 打开 App：进会话页，权限卡 sticky，下面是对话；卡上的三键与通知上的一样。

三种事件，对齐 Lody

type何时推送收件箱分段
session.waiting会话从跑变成等你（权限框 / 选择框 / y-n）是，可操作需要你
session.doneagent 一轮结束（转录里 assistant 收尾且 60s 无新输出）或 agent 退出码 0是（可在设置里关）刚做完
session.erroragent 非零退出 / keepalive 判死 / 内存告警（把 memalert 那条也接进总线）是出错了
Web Push 是唯一通道，不是过渡：iOS PWA、Android PWA、Android TWA 收的都是它。部署者不需要注册任何东西，VAPID 密钥在 ~/.roami/push/ 首次启动自动生成。

§7 接入：连通性和证书都是部署者的事手机版只认「一个 https 地址 + 一个 token」

连通性：不在本稿范围

手机得能访问到你部署 Roami 的那个 https 地址——这和桌面浏览器访问 Roami 是同一个前提，手机版没有新增任何要求，Roami 不做也不承诺。内网 WiFi、公司 VPN（WireGuard）、Tailscale、frp、Cloudflare Tunnel，随部署者选，文档只写这一句。对照：Orca 同样不管；Lody 和 Codex 手机版「管了」，方式是各自运营一个云端中转（机器出站连云、手机连云），那是有中心的产品才能做的事，也是它们闭源 / 收费的部分，Roami 是自托管，没有这一层。

证书：也是部署者的事，Roami 只提醒

PWA 收推送的前提是证书被手机系统信任。Roami 默认自签，桌面浏览器和 Android Chrome 点一次「继续访问」就行，推送照收；iPhone 不认自签，要么在手机上装一次 Roami 的 CA（/cert.crt，设置 › 通用 › VPN 与设备管理 › 安装，再到 关于本机 › 证书信任设置 里打开），要么部署者自己配一张正式证书（有域名的话 acme.sh DNS 验证签 Let's Encrypt，覆盖 ~/.roami/tls/）。不做 roami cert，不要求域名（2026-09-25 拍板）：这和连通性一样是部署者自己能做的事。

Roami 该做的（就这一件）

启动日志和 设置 › 关于 里明说「证书是自签的，iPhone 收不到推送」，给 /cert.crt 链接和两条路的说明；改 tls_san 时自动重签（今天要手删旧证书）。

配对 = 扫码

桌面 设置 › 关于 生成二维码 {url, pairToken}，token 一次性 10 分钟。手机（已经连得上那个地址）扫码打开 → 换长期 token → 引导「加到主屏」→ 申请通知权限。不用输地址、不用记密码。

多台机器

PWA 里存多个部署（URL + token），「我 › 机器」切换；有 cluster hub 的部署一个 URL 管全部，推送由各机器自己发（hub 只是反代）。

后端出网

发推送要机器能访问 Apple / Google / Mozilla 的推送网关。内网机器可以让 hub 代发（sink 加一个 via）。

§11 风险

iPhone 要多一步

iPhone 不认自签证书，收推送前要装一次 Roami 的 CA。对策：关于页把步骤和 /cert.crt 链接写清楚；手装 CA 的 PWA 能否收推送尚未验证，不通的话 iPhone 就得靠部署者自己配正式证书。

国内安卓的推送网关

Android Chrome 的 Web Push 经 Google 的网关（fcm.googleapis.com），国内部分网络不通、部分厂商 ROM 杀后台。对策：前台时走 WebSocket 直接收事件不依赖推送；文档提示把 Chrome 加白名单。iOS 走 Apple 网关，国内可达。

抓屏判「等你」的误报

TUI 重绘残帧会闪一下 waiting。3 秒去抖 + 已有的 advancePromptSignal 连续两次确认；误推一条比漏推一条便宜。

iOS PWA 的限制

推送必须加到主屏后才有；通知按钮藏在长按 / 下拉里；没有震动 API。对策：配对流程里把「加到主屏」做成必经一步，权限卡在 App 内也能批。

电量

后台不做轮询，全靠推送唤醒；前台轮询频率沿用桌面（1.2s 只对当前会话）。

后端出网

发推送要机器能访问 Apple / Google / Mozilla 的推送网关。内网机器可以让 hub 代发。
